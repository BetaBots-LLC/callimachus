`cal` can now build and refresh the index without the desktop app. Four new `cal` commands run the app's background jobs from a terminal: `cal index` builds or refreshes the index from every agent's history (exit code 1 when a session could not be indexed), `cal watch` keeps it fresh as agents write (one line per batch), `cal embed` builds the semantic index (it downloads the embedding model once; `cal embed --no-download` uses only a model already there), and `cal distill --auto` distills recent sessions under the daily cap. `cal distill --auto`, like the drain `cal watch` runs, uses the memory engine turned on in the app's Settings > AI engine: once memory is on it runs with the app closed (a logged-in `claude` or `codex` CLI and local Ollama need nothing else, and an API key comes from the OS keychain where the app saved it), and on a machine that never ran the app it says memory is off. Only one process watches or distills an index: `cal watch` refuses to start while the app is open, and the app leaves live indexing to a running `cal watch` (Settings > Index says so) and takes over within a minute after it stops, and it starts no auto-distill round while `cal watch` or `cal distill --auto` runs. A second app open on the same index now waits the same way instead of running a second watcher. `cal distill --auto` refuses while the app or `cal watch` runs, since both distill on their own. The standalone `cal` and `callimachus-mcp` binaries and the Docker image now build without GTK or WebKit (the released binaries never loaded them at run time).
