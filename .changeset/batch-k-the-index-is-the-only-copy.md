"callimachus": patch

Your index is backed up, failures show up instead of passing silently, and one bad call no longer breaks the rest.

- **Snapshots on macOS.** Before each schema upgrade, and once a week after an integrity check (`PRAGMA quick_check`), the app keeps a copy of the index in `snapshots/` next to it. They are APFS clones: taken in milliseconds, free at first, and growing only as the index changes (a snapshot from before this release's one-time vector rebuild ends up holding about 650 MB of a 5.3 GB index). One weekly snapshot is kept, and the pre-upgrade one for 7 days or until that rebuild succeeds. Nothing is ever deleted to make room: while the disk has less free space than the index, no snapshot is added (a weekly one still replaces the last weekly one, which frees what the old one held). Shrink index and Reclaim space remove the automatic ones, since the rewrite would make each a full copy (the weekly one stays while the last integrity check had failed). Each index has an identity of its own, so a new index started in the same folder never removes the old one's snapshots. Settings → Index & storage lists them with what they cost on disk, and says so when the index's disk cannot clone files. Linux and Windows get no automatic snapshots yet.
- **Restore a damaged index.** When the index cannot be read at startup, the error screen offers "Restore the snapshot from <date>": it checks the snapshot first (`PRAGMA quick_check`, falling back to an older snapshot when it fails), puts it in place, keeps the damaged files beside it as `index.db.damaged-<date>` (nothing is deleted), and says what is lost (what was indexed after that date; sessions still on disk come back with the next index pass). It refuses while another process, an agent session's MCP server included, has the index open (and where nothing can tell, except on Windows, where the swap itself fails safely). A restore cut short halfway is recognized: nothing opens the index until the app has finished it. A copy taken by an upgrade that then failed is removed, and never displaces an older snapshot. The screen no longer promises that a rebuild brings everything back: it says how many Claude Code sessions in the index have no transcript left.
- **`cal backup [--to DIR]`.** Saves a copy of the index (a free clone on APFS, else a full copy through SQLite's online backup, refused when the disk has less free space than the index plus 10%), for machines without the app and for systems without clones. It never upgrades or creates the index.
- **Owner-only files.** On macOS and Linux the index folder is created readable only by you, the app and `cal` make `index.db` and its `-wal` and `-shm` owner-only (0600) when they open the index for writing, and `index.db.index.log` is created owner-only. A folder you chose with `CALLIMACHUS_DB` keeps its mode, and read-only tools and hooks change nothing.
- **`cal doctor`** (and Settings → General → **Copy diagnostics**) reports what decides whether Callimachus works on this machine: the index and its schema against this binary, free disk space, who holds the locks next to the index, each agent's hooks and MCP entry and whether the binaries they run still exist, the embedding model and vector table, the snapshots and the last integrity check, Claude Code's transcript retention, the hooks that gave up in the last seven days, and each source's parse health. `--json` (and `--json-version 1`, schema at callimachus.app/schemas/cal/doctor.v1.json) for scripts; `--quick-check` adds SQLite's integrity check. It is read-only, shows your home folder as `~` and holds no project text, so it can go straight into a bug report. The bug report form now asks for it.
- **Hooks say why they gave up.** Hooks still exit silently on any error, so your agent never sees one, but each failure now leaves one line in a local file next to the index (`ledger.skips.jsonl`) with its class (the index needs an upgrade or is newer than this binary, it stayed locked, the agent sent input this version cannot read, a crash, or another error), which `cal doctor` counts. Nothing is recorded when there is no index, and nothing leaves the machine.
- **Transcript format changes are caught.** Every indexer now counts the records it could not parse and the record types it does not know, per source and pass, and compares each pass with that source's own recent passes. When an agent's records suddenly go unread (an update renamed a record type, or most files of a pass stop yielding any message), Settings → Index & storage says so and `cal doctor` names the types, before the agent's own cleanup deletes the originals. It also works while the app runs, where files arrive one at a time: small batches are summed until there is enough to judge. Sources that are always a little noisy never warn, a warning ends when a full pass reads clean again, and dismissing one keeps the same change quiet for 30 days.
- **A panic no longer breaks every later call.** A bug that panicked while holding the index connection used to make every later MCP tool call, and every app command and background job that writes, fail until a restart. The next caller now gets the connection back, with any half-done write rolled back.
- **More secrets redacted.** Everything that leaves the machine (MCP results, hooks, LLM prompts, exports, `cal` output) now also redacts GitLab, npm, Hugging Face, PostHog personal, Groq, xAI, Perplexity, Replicate, Supabase secret, DigitalOcean, Shopify, Linear and SendGrid keys, age secret keys, Google OAuth access tokens and client secrets, `Authorization: Basic` credentials, the value after a `--token` / `--api-key` / `--password` flag, `passwd`, `credential` and `AccountKey` assignments, and a token used as the user name of a URL (`https://<token>:x-oauth-basic@github.com`). Ordinary text that only looks similar is left alone: identifiers that share a prefix (`npm_config_cache`, `hf_hub_download`), slash lists after the word basic, flags such as `--password-stdin` or `--token-file`, paths and `credential_source`-style settings. A long run of key-like names no longer slows the scan down.
- **Checked, not promised.** Tests now run the hooks, the read-only `cal` commands and every MCP tool against an index one and two schema versions old and fail if any of them errors or changes it; committed migrations are pinned by hash; network clients outside the documented egress paths fail the build (SECURITY.md); nothing but `cal` may print to stdout, which the MCP server uses for its protocol; and redaction, control stripping, fence escaping and the memory and transcript budgets are property-tested on thousands of generated inputs.
